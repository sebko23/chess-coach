## 0. The problem at hand

BBF-87 shipped a v2 narrative corpus (`tests/gold/narrative/v2/corpus.json`,
30 entries) but no production code loaded it. The corpus was inert:
useful for unit tests of the validator but not for the actual
narration pipeline.

The wiring needed:
- A FEN → entry lookup (GroundingIndex).
- A prompt-formatting helper (build_grounding_block).
- A validator that checks the LLM's `<grounding>` tags against the
  matched corpus entry (word-LCS similarity).
- A migration to make the `narrations.position_id` column nullable
  (pre-existing bug: the route was passing FEN strings where the
  schema expects a UUID referencing `positions.id`).

## 1. What ships

### 1.1 New: `services/chess_coach/narration/grounding.py` (208 LOC)

- `GroundingIndex` (FEN → entry)
- `GroundingMatch` (corpus excerpt for a hit)
- `build_grounding_block` (LLM-prompt formatting)

### 1.2 Modified: `services/chess_coach/narration/pipeline.py`

`NarrationPipeline` now takes a `grounding` arg. The `explain()`
coroutine returns `(narration, corpus_entry_id)`; `corpus_entry_id`
is None when the FEN has no v2 match. The `explain_simple()` wrapper
passes through to `NarrationOutput.corpus_entry_id`.

### 1.3 Modified: `services/chess_coach/narration/prompt.py`

`SYSTEM_PROMPT` gains a citation rule for `<grounding>...</grounding>`
tags. `build_user_prompt()` accepts an optional `grounding_block`
(prepended to the engine analysis).

### 1.4 Modified: `services/chess_coach/narration/validator.py`

New `<grounding>` tag parser; new word-LCS similarity check (≥ 30
words OR ≥ 50% overlap) against the matched corpus entry's
`narrative_explanation`. `validate_citations()` takes an optional
`grounding_match` arg; when None (no FEN match), the grounding
check is skipped (no fault for not producing tags the prompt didn't
request).

### 1.5 Modified: `services/chess_coach/narration/__init__.py`

Re-export `GroundingIndex`, `GroundingMatch`, `build_grounding_block`.

### 1.6 Modified: `services/chess_coach/gateway/app.py`

Load `GroundingIndex` at startup; pass to `NarrationPipeline`. The
new import is marked `# noqa: E402` to follow the existing app.py
E402 pattern.

### 1.7 Modified: `services/chess_coach/gateway/routes/narration.py`

Include `corpus_entry_id` in the INSERT into narrations; pass through
to the route response.

**Pre-existing bug fixed:** `position_id` was passed as `body.fen`
(a FEN string) where `position_id` is a TEXT column with FK →
`positions.id`. The new migration 0008 makes `position_id` nullable,
removing the FK violation; the route still inserts `body.fen` so
audit captures the narrated FEN.

### 1.8 Modified: `libs/chess_coach/protocol_types/narration.py`

`NarrationResponse` gains nullable `corpus_entry_id` field.

### 1.9 New: `libs/chess_coach/storage/migrations/0008_narrations_corpus_entry_id.sql` (80 LOC)

Portable table-rebuild pattern (rename, recreate, copy, drop) to
add `corpus_entry_id` and make `position_id` nullable. Avoids
`ALTER TABLE ... ALTER COLUMN ... DROP NOT NULL` (requires SQLite
3.35+; cited in the migration comments).
